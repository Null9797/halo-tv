# HaloTV 3.2.2 · 独立版迁移与桌面守护交接修复

本次提供 Standard、Guard、Lite 三个独立版，沿用独立包名和签名。Standard / Guard 内部号 **218**，Lite **73**；可覆盖升级同类型独立版。

## 为什么迁移后容易失效

资料导入不能继承新包的无障碍、通知使用权、自动恢复权限和厂商自启动设置。之前的导入流程会提前请求旧守护退出，但没有等待新守护准备好、核实交接回应；部分设备的厂商开机入口仍指向旧包。这些路径已作修复，但不能据此认定所有用户反馈均由同一原因造成。

## 本次修复

- 将“资料导入”和“桌面接管”分开。导入后进入接管检查页，新守护在确认交接前暂不拦截 Home；先确认新守护已连接，或 Standard 已成为默认桌面，再请求旧版退出。
- 核验过渡版包名、签名和类型，检查其交接回应及旧守护登记状态。失败保留待处理状态，不再把资料导入成功当作守护交接成功；不按包名自动停用 Aerial。
- 已记录迁移、但尚未完成新检查的用户升级后会得到一次检查入口。正式版也可从“控制中心 → 设为主屏幕 → 独立版桌面接管检查”再次打开。儿童模式生效时不自动弹出检查页。
- 系统无障碍中的名称增加“独立版”，减少误开旧服务。页面分别显示实际连接、自动恢复、通知使用权、默认桌面状态；仅显示已登记不等于实际运行。
- 对仍指向旧 HaloTV 的已存在厂商开机组件，提供明确的修复按钮，先备份原值再写入、读回确认。需要系统允许写入；不会创建未知厂商设置，不会改其他桌面的开机入口。
- 桌面守护工具补充 AUTO_START 厂商授权别名；显式修复时持久化开启恢复意愿，并提示旧开机入口残留。保留其他无障碍服务，不卸载、停用系统应用。
- 修复正式版和 Lite 在跳转迁移页后，剩余生命周期回调访问未初始化桌面的问题。
- Lite 增加对应的默认桌面迁移检查；Lite 仍不包含完整桌面守护。

## 迁移用户怎么操作

1. 覆盖安装与当前类型一致的 3.2.2 独立版，保留现有设置与素材。
2. 打开“独立版桌面接管检查”，按提示重新开启独立版守护及所需权限。Standard / Lite 可选择独立版为默认桌面；Guard 不注册默认 HOME。
3. 若提示开机入口仍指向旧版，先修复；再点击“确认接管并检查旧版退出”。不能完成时页面会说明原因，可按配置帮助使用电脑端工具。
4. 分别测试 Home、待机唤醒和重新开机，确认独立版及素材正常后再自行卸载旧 HaloTV。不要误卸载保留使用的 Aerial。

新安装且不存在过渡版的用户不会被强制进入迁移流程。已有守护不会因升级自动改为关闭；用户主动关闭的恢复选择也不会在后台被悄悄打开。

## 检查范围

Standard / Guard 各 **492** 项、Lite **151** 项单元测试，以及守护工具 **27** 项测试通过。三个 Release 构建、Android Lint（无 Error/Fatal，仍有 Warning/Hint）、包名、版本、ZIP 完整性、对齐和 v1/v2 签名校验通过。未运行模拟器、未操作电视；反馈机型的 Home、待机和冷启动实际效果仍需验证。

不承诺突破所有厂商限制或永久不掉守护。缺少系统授权、受限设置或厂商禁止自启动时，仍需用户在系统或电脑端配置。本版未更换启动图，也未新增远程公告弹窗。

官网优先下载、GitHub 备用。旧包名更新清单继续提供 3.1 过渡版；已安装过渡版的用户可安装最新同类型独立版。完整源码附件为 `HaloTV-3.2.2-source.zip`，包含应用、Lite、测试及守护工具，不含私钥或本机配置；GitHub 自动生成的 Source code 是发布材料仓库快照。
